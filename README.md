# MiniEngine

> 用 **C++20 + 标准库** 写的**终端 2D 游戏引擎**实验：Windows only、**零第三方依赖**、渲染只走字符 + ANSI 转义序列，不需要任何图形 API。
>
> *A dependency-free 2D game engine in C++20 that renders a playable game entirely inside a terminal. Windows only.*

**状态**：**v0.4「看得清」已达成**（可玩的一局 + 三个调试出口：`T` 面板 / `F2` 几何层 / `F7` 列表）· `VersionString()` = `0.4.0-dev` · 用例 **220 条**（23 个 suite）· 反向验证 **17 场**（S10 的 12 + S11 的 5）· 人眼验收 **47 条**（S10 的 28 + S11 的 19）· 可试玩 demo（S11.5）。

## 跑起来

需要 **Windows** + **MSVC 2022**（生成器 `Visual Studio 17 2022`）+ **CMake ≥ 3.20**。

```powershell
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
.\build\bin\Debug\MiniEngine.exe
```

⚠️ 生成器是**多配置**的：`--build` 与 `ctest` 都必须带配置（`--config Debug` / `-C Debug`），漏了会得到"找不到可执行文件"。

## 给别人试玩（不用装编译环境）

包是**一个 zip**：`MiniEngine-Demo-v0.4.0-windows-x64.zip`（exe + 启动器 + 玩家卡，约 **174 KB**）。

- **拿包**：本仓库 **Releases 页面**（`v0.4.0` 的资产）；或自己打一个：

  ```powershell
  powershell -File tools\pack_demo.ps1     # ⇒ dist\MiniEngine-Demo-v0.4.0-windows-x64.zip
  ```

- **对方要做的**：解压 → 双击 **`开始试玩.cmd`**。不需要 Visual Studio / CMake / VC++ 可再发行组件
  （exe 用**静态 CRT** 编译，依赖表里只有系统 DLL）。
- **正文**（键位表、已知限制、反馈方式）在 `doc/RELEASE_NOTES_v0.4.md`；包里那份叫 `玩法与已知限制.txt`。

⚠️ 两点如实说明：**未做数字签名**（首次运行可能弹 SmartScreen ⇒ 点"更多信息 → 仍要运行"）；
**ConPTY 终端**（Windows Terminal / VS Code）里"按住移动"会退化、窗口也不会自动放大
⇒ 所以启动器**优先用经典控制台**（`conhost.exe`），在那里面长按与自动放大都正常。

## 操作

| 键 | 作用 |
| --- | --- |
| `WASD` / 方向键 | 移动（八向） |
| `SPACE` | 开火（弹药有限，打光只能靠击杀返还接续） |
| `ENTER` | 标题屏开始（**只在标题屏有效**） |
| `ESC` | 暂停 / 恢复；`GAME OVER` 时回到标题屏 |
| `R` | `GAME OVER` 后立刻重开（世界重铺、实体 id 不复用） |
| `T` | **Debug Overlay**：右上角实时面板（帧时间 / 分段耗时表 / 游戏计数），默认关 |
| `F2` | **几何层**：实心格与实体占格的**底色**可见（字形不变），默认关 |
| `F4` | 写一份调试快照到 `miniengine_debug.log`（带 `[时间][级别]` 前缀） |
| `F7` | 敌人状态面板（逐敌 `state / distance / tile`；暂停 / 结算时也能开） |
| `Z` / `C` | **原地转身** 45°（逆 / 顺时针；⚠️ 受玩法门控 ⇒ 暂停时无效） |
| `V` | **切 2D / 3D 视角**（第一人称走廊 ⇄ 俯视地图；`F5` 是备份键。⚠️ 3D 里看不见自己/敌人 —— 精灵留到 S13） |
| `Q` | 退出 |

一局是什么样：开局是**标题屏** → `ENTER` 后刷**第 1 波 3 个敌人** → 被追打、开火反击 → `ESC` 暂停（**世界完全冻住**，连波次的喘息倒计时都停）→ 掉血归零 → `GAME OVER` → `R` 重开。

HUD 两行（**58 / 64 列**）：`pos / tile / sumdt / v` + `hp / ammo / kills / wave / dir`。波次 `3 → 4 → 5 …` 封顶 8；弹药 18，每击杀返还 1 发（**净耗 2 发/敌人** ⇒ 打得准就够用，失误才缺）。

**三个调试出口的分工**（都默认关）：`T` = **摘要**（引擎帧数据 + 分段耗时表 + `wave/foes/shots/hp/ammo/geom`）、`F2` = **图层**（只改底色、不动一个字符）、`F7` = **列表**（逐敌状态）。按 `T` 之后，"渲染占了多少 ms"就是面板上的一行数字。

## 5 个技术点

**① "暂停"的正确形态是矩阵，不是 if**
问题：暂停要停的不只是玩家，而是"AI / 积分 / 开火 / 时钟 / 波次"五项，**漏停一项就是 bug**。
决策：把状态机做成**纯函数 + 策略表**（`game/GameState.h`，只 include `<cstdint>`），并用 `static_assert` 把"**有且只有一个状态会模拟世界**"钉在**编译期**。
代价：多一个文件 + 13 条用例；表里只能说"跑不跑"、不能说"怎么跑"。
证据：`game/include/game/GameState.h` · 用例 `GameState.OnlyPlayingSimulates` · 反向验证 R1（改坏它**编译就过不去**）。

**② 实体 id 永不复用**
问题：悬空 id 一旦被新实体复用到，会**静默指错对象**（比崩溃更难查）。
决策：重开时**不重建 `World`**（那会重置 id 计数器），只用既有原语清空实体、让计数器保持单调 ⇒ 悬空 id 最坏只是"**找不到**"。
代价：清空清单要手写 7 步；且"不许重建"这条禁令**没有机器守卫**（见 ④）。
证据：`Game::StartNewRun()` · 用例 `Game.RestartLeavesNoStaleState` · `doc/S10_CHECKLIST.md` 分叉②的"漏一行会怎样"对照表。

**③ 测试是不是真的在守门：故意改坏，看它响不响**
问题："全绿"不等于"那道门有人守"。
决策：每个阶段主动**破坏关键机制**（12 场），走"预测红集 → 实测红集 → 逐条比对"。
结果：**8 场真的红了**（最狠的一场红在**编译期**），**5 场是绿的** ⇒ 那 5 处**如实登记为"没有机器守卫"**，不假装它们被守住。
证据：`doc/S10_CHECKLIST.md` §10.3.2 / §10.3.3（含**两条预测失误**的复盘）· 台账 **C28**、**C32~C35**。

**④ 一次 UB 全绿的收获**
问题：把"遍历中清理容器"改成 UB 写法之后，**197 条用例一条都没红、也没崩**。
决策：不把"没崩"当成"没问题"，而是登记成一条**带触发条件**的债，并写明它只靠注释与契约在守。
代价：目前只能人肉 `grep`。
证据：`doc/TECH_DEBT.md` **C28** · 反向验证 **R9**。

**⑤ 分层是拿"零改动"量出来的**
问题：怎么证明游戏逻辑没有烂进引擎？
决策：把"**某个阶段对 `engine/` 的改动行数**"当硬指标。
结果：S10 这一整段（状态机 + 波次 + 弹药 + 重开 + 验收）对 `engine/` **零改动**。
证据：`git diff --stat <S9末端>..<S10末端> -- engine/` **输出为空** · `AGENTS.md` §1.4。

## 目录

- `engine/` —— 引擎：终端 IO（Windows 控制台 + ANSI）、帧缓冲与**行差分**渲染、时间与限帧、数学（`Vec2`/`AABB`/`Ray`）、世界与碰撞、相机、敌人 AI 状态机。**不认识任何游戏概念**。
- `game/` —— 一个具体的游戏：地图、波次、弹药、HUD、状态机接线。**只 include 引擎的公共头**。
- `tests/` —— 自研的 MiniTest 框架 + **220 条用例**（23 个 suite）。
- `tools/` —— 开发侧脚本：**打包 demo**（`pack_demo.ps1`：构建 → `dumpbin` 零依赖自检 → zip）+ 打进包里的启动器与玩家卡。**不进 CMake、不参与构建**。
- `doc/` —— 施工图与台账：前置事实、坑表、逐条落地偏差、反向验证记录、技术债。**判断过程都在这里**。

## 已知限制（照实写）

- **只支持 Windows + MSVC 2022**：平台层只保留一条实现路径，没有 Linux / macOS 分支。
- **依赖终端类型**：在 ConPTY 系终端（VS Code 内置终端 / Windows Terminal）里**收不到真正的 key-up** ⇒ "按住移动"会退化成"每次按键走一帧"。
- **实体之间没有推挤**：两只敌人可以叠在同一格，屏幕上只画得出一个 `E`（有意不做，台账 **C12**）。
- HUD 里**不出现** `ESC` / `ENTER` 这类含 `E` 的键名 —— 屏幕是唯一的观察面，用例靠数屏幕上 `E` 的个数来数敌人。
- `T` / `F2` / `Z` / `C` / `V` 这几个新键**能不能收到只有人眼知道**：用例全走假输入（绕过真实键盘），而 `F1` / `F3` 在本机都被别的软件抢占过（台账 **C37**）。按下去屏幕没反应就先怀疑这个 —— 换键都只改一处常量（`Game.cpp` 顶部）。
- 版本字符串是 `0.4.0-dev`：**已达成 v0.4，但这棵树还在往 v0.5 走**（`-dev` 后缀的含义）。

## 这个仓库是怎么做出来的（照实说）

需求、架构、验收标准、每一步的取舍与**反向验证**由我设计并逐条记录；**实现有 AI 参与** —— 仓库根的 `AGENTS.md` 写着完整协作约定（AI 只编辑文件，构建与运行由我执行）。每一行我都要能解释，关键机制都做过"故意改坏看用例响不响"的验证。

这个仓库里**文档比生产代码多**（`doc/` ≈ 11.9k 行 vs 生产代码 ≈ 6.0k 行，约 **2 : 1**）。想看判断过程而不是结论，从下面进。
