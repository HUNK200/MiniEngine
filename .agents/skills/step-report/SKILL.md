# 步骤报告格式（固定 7 节）

> `AGENTS.md` §1.4 规定：AI 只改文件，**构建 / 运行 / 验证由使用者做**。
> 本 skill 规定"交付时那份报告长什么样"。**写报告之前先读完它。**

## 为什么是这 7 节

使用者要**不翻 diff** 就能回答三个问题：

| 他要回答的问题 | 靠哪几节 |
| --- | --- |
| 你动了什么？每一处是干什么的？ | §1 + §2 |
| 我该做什么？应该看到什么？出错怎么认？ | §4 + §5 |
| 这一步值不值？现在到哪了？ | §6 + §7 |

⚠️ 两条红线（来自 `AGENTS.md`）：
- **不许写"构建通过 / 已实测"**，除非那个结果确实是使用者回报的（AI 无法自证能编译）；
- **"作用"不许写成卖点** —— 要写它**挡住了哪个具体的失败**；写不出来就照实说"这一步只是把某件事写进结构"。

## 7 节骨架（顺序固定，标题可微调）

### 1. 文件清单

一张表：`文件 | 动作（新建 / 改 / 删）| 规模（行数）`。
末尾补一行 `engine/`（或"未动"）—— 本项目反复拿"engine 零改动"当**分层正确**的证据，要显式写出来。

### 2. 逐部分说明："一处改动 = 一个作用"　★ 本报告的重点

- **新文件**：按"部分"逐个列 —— 枚举 / 常量 / 结构体 / 函数 / `static_assert` / 注释块都算一个部分。
  四列：`# | 部分 | 它做什么 | 谁用 · 不写它会怎样`。
- **新用例**：每条一行：`# | 用例名 | 具体检查什么 | 红了说明什么（故障现象）| 反向验证靶子`。
- **改已有文件**：逐行说明"这一行改变了什么行为"。
- ⛔ **只写"改了哪个文件（路径 + 干什么用的）"不算完成这一节** —— 那是上一版的偷懒写法，使用者明确要求加细。

**反例 → 正例**（"作用"那一列）：

| ❌ 反例 | ✅ 正例 |
| --- | --- |
| `GameState.h \| 新建 \| 状态机` | `enum class GameState \| 四个状态，初值 Title（= PLAN 的"开局提示 → 按 Enter"）\| Game::m_state（步骤 2）；用例断言 State()==Paused 不用比浮点/字符串` |
| `tests/CMakeLists.txt \| 加一个源文件` | `加 test_gamestate.cpp 一行 \| ★ 不加就**根本不编译**这个文件 —— 症状是 mini_tests.exe GameState 报 no case in suite（本项目 S0 明确禁用 file(GLOB)，防的就是"忘了加文件⇒静默漏测"）` |

### 3. 关键映射表

把这一步引入的"**数据 → 行为**"关系画成一张表，让使用者一眼看到"改哪个数会出什么事"。

例：策略字段 → 对应业务步骤 → **关掉的后果** → **忘了关会出的具体故障**。

### 4. 使用者要执行的命令

原样可粘贴的 **PowerShell** 代码块，含本项目惯例（第一步永远 `cmake --version` 核版本，三台机三版本）。
⚠️ **新增源文件时必须显式给出"重新配置"那一条**（`cmake -S . -B build`），并说明**不加会怎样**。

### 5. 期望看到什么 + 最容易出错

- 一张表：`检查项 | 期望`，期望必须是**具体数字 / 退出码 / 现象**。
- "最容易出错"**按概率排序**，每条给三样：**现象特征** + **判据** + **是不是代码错**（避免使用者去查错方向）。

### 6. 这一步挡住了什么具体失败

- 每条作用都写成"**它挡住了哪个具体的失败**"（`AGENTS.md` §1.1 的要求）。
- **超出方案范围的小增项**要单独列出来（"不要我就删"）。
- **需要使用者拍板的偏差**也列在这里：给方案 + 让他定，不要自己替他决定。

### 7. 进度与状态

- 一张表：阶段进度（第几步 / 共几步）· 用例数（旧 → 新 + 预期总数）· `engine/` 改动 · 工作区状态 · 已提交的 commit。
- 结尾一行**状态标签**：**"代码已写完，待构建 / 待运行 / 待肉眼验"**。
- 末尾一句话预告下一步，但**不要开始做**（`AGENTS.md` §1.1：等审核后继续）。

## 及格线（写完自查）

- [ ] §2 里**每一处改动**都写了作用，且作用能落到"**不写会怎样**"
- [ ] §3 有那张"数据 → 行为"的表（没有新映射关系时，可省并说明为什么）
- [ ] §4 的命令**原样可粘贴**，没有"你可以考虑…"
- [ ] §5 的期望值有**数字**，错误排查给了**判据**
- [ ] §6 写的是**具体失败**，不是"提高了可维护性"这类卖点
- [ ] §7 有状态标签
- [ ] 全文**没有**"构建通过 / 已实测"（除非使用者回报过）
