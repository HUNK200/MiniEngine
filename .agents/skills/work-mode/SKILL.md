# 上班模式（入口转发）

本 skill 的正文**不在这个目录**，而在项目的 `doc/` 下，以避免同一份内容维护两处：

- 相对本文件的路径：`../../../doc/WORK_MODE.md`（**只认这一条**）

> ⚠️ **不要把绝对路径写进仓库**（2026-10-02 踩过）：这里原来写着某台机器的
> `d:/<某台机器>/…/doc/WORK_MODE.md`。换一台机器（仓库搬到 `D:\<另一台机器>\MiniEngine`）
> 之后，本 skill **整体失效**（读不到正文），而且它违反 `AGENTS.md` 第 5 节"绝不提交含绝对路径的文件"。
> ⚠️ 2026-10-13：上面这行**连"反面例子"里的盘符也一并脱敏了** —— 例子本身不该把本机路径带进仓库。
> 真要绝对路径时，用"本文件上溯三级"现算 —— 别把盘符写进来。

配套文档都在仓库根的 `doc/` 下（**不在本目录**）：`MiniEngine_PLAN.md`（阶段定义、H 节长期路线、E 风险表）、`S7_CHECKLIST.md`（最新施工图；`S6_CHECKLIST.md` 是上一阶段，`S0_CHECKLIST.md` 是历史留档）。

## 执行方式

1. **先读取 `../../../doc/WORK_MODE.md`**（相对本文件解析），按其中的"触发后的固定动作""输出模板""微任务准入标准""禁止的 6 类伪任务""类型轮换表"执行。
2. 判断当前阶段时读 `../../../doc/MiniEngine_PLAN.md`，并以 `git log --oneline -5` 为准。
   （原来这里还有一句"S0_CHECKLIST 勾选进度兜底"，项目已到 S7，2026-10-02 删掉 —— 它只会让 skill 去读过期清单。）
3. 所有相对路径以**仓库根**为基准解析；仓库根 = 本文件上溯三级（`.agents/skills/work-mode/` → 根）。
4. 本文件**不含任何正文**，不要在只读了本文件的情况下直接开始给任务。

## 四条最容易违反的铁律（提前提醒）

1. **只给一个任务。** 不要给 3~5 个选项让用户挑。
2. **触发后不要反问。** 只有在完全判断不出当前阶段时才问一句。
3. **任务必须自带起手式**：打开哪个文件、哪一行、改成什么。没有这个就不算合格任务。
4. **只发任务卡，不代写实现。** 代码一律由使用者自己敲（`AGENTS.md` 核心约定）。明说"你写"才动手。

## 为什么要有这个转发文件

Agent Skill 的发现路径是 `.agents/skills/<name>/SKILL.md`，而文档被统一放在 `doc/` 下（可见、可直接编辑、和其他文档并排），两者对不上。转发文件是调和：**正文一份，入口一个。**

如果不想要这个结构，二选一：

```bash
# 方案 A：彻底改成标准位置（正文搬进来，删掉 doc/ 里那份）
cd <仓库根>        # 例如 <某台机器上的仓库路径> —— 别把盘符写进仓库（2026-10-13 脱敏）
mv doc/WORK_MODE.md .agents/skills/work-mode/SKILL.md
# 然后删掉本文件的前 4 行之后的所有"执行方式"内容，并把 frontmatter 保留

# 方案 B：改成个人级，所有项目可用
mkdir -p ~/.agents/skills/work-mode
cp .agents/skills/work-mode/SKILL.md ~/.agents/skills/work-mode/SKILL.md
# 注意：方案 B 下"上溯三级"会落到 ~/.agents 而不是仓库根 —— 复制出去之后要把
#       `../../../doc/...` 换成显式传入的仓库根，否则读不到正文（2026-10-02 记录）
```

## 安装 / 校验命令

```bash
# 确认文件结构
ls -la .agents/skills/work-mode/SKILL.md
head -n 5 .agents/skills/work-mode/SKILL.md

# 确认名字与目录名一致（name 必须是 work-mode）
grep '^name:' .agents/skills/work-mode/SKILL.md
```

安装到 `.agents/skills/` 后，客户端可能**需要重载或重启**才会发现这个 skill。
