# 上班模式 —— MiniEngine 碎片时间微任务开关

> 一句话：把 MiniEngine 的阶段切碎成 **5~10 分钟、随时可被打断、且能立刻验证**的小动作。
> 这个文件不是学习计划，也不是任务清单，它是"现在这点空档，我干一件什么事"。
>
> 已确认的设定：**能构建能跑**（工作机上有 VS Code + 这份代码）、**任务由 AI 现编**。
> 因为现编，下面"准入标准 + 禁止清单 + 类型轮换表"就是这个开关的性格，改它们等于改开关本身。

---

## 1. 触发词

| 你说 | 行为 |
| --- | --- |
| 上班模式 / 摸一下鱼 / 给我个 10 分钟的活 / 碎片任务 / 来个小活 | **10 分钟档（默认）** |
| `/w5` | 5 分钟档 |
| `/w10` | 10 分钟档 |
| 「只有 3 分钟」 | 3 分钟档（只允许：改一个值 + 看一次输出） |
| 「做完了」 | 给下一个，**不得与前一个同类型** |
| 「太简单」/「太难」 | 同一赛道内升/降一档，**不许换阶段** |
| 「今天不方便编译」 | 切纯推演档（只在对话里做，不碰代码文件） |

**触发后不要反问。** 直接给任务。唯一允许的一次反问：`git log` 和对话都判断不出当前阶段时，问一句"现在到哪个阶段了？"

---

## 2. 触发后的固定动作（顺序执行，不许跳）

1. **判断当前阶段**。优先 `git log --oneline -5`；再对照 `MiniEngine_PLAN.md` 的 B 节阶段列表（S0~S14）；再回顾对话里最近做的东西。三者冲突时**以 git log 为准**。
2. **挑一个动作**，它要能让当前阶段往前挪一格（不是"做完了但阶段没动"）。
3. **套用第 3 节的输出模板，只输出一个任务。**

---

## 3. 输出模板（必须照抄结构，≤ 15 行）

````text
[任务] <一句话标题>  —— 预计 7 分钟
为什么是现在：<一句话，指到具体的阶段/文件/已知风险编号>

动手：
  1. <文件:行> → <把 X 改成 Y>
  2. 增量构建：cmake --build build --config Debug

完成标志：<一条命令，或一个能立刻看到的现象>
被打断怎么办：<说清"直接丢/改回去/commit"都不留半成品>
````

第 1 步必须细到"**打开哪个文件哪一行、改成什么**"。上班空档最贵的是上下文重载，不是时间——用户不该在开始动手前还要自己找代码。

---

## 4. 微任务准入标准（5 条，不满足就把任务砍小到满足）

1. **时间盒达标**。预算里要**扣掉 10~30 秒的增量构建时间**，所以 5 分钟档真正能写代码的只有约 3 分钟。
2. **可中断**。任何时刻被叫走，都不会留下"编译不过"或"半改完的接口"。
3. **一条可执行的完成标志**。一条命令，或一个立刻能看到的现象。不接受"代码更干净了""大概没问题"。
4. **归属某个 S 阶段**，且是当前阶段或紧邻的下一个。**不许跳级**（在 S1 就别给 S12 的活）。
5. **自带起手式**。用户看完不需要再思考"从哪下手"。

粒度锚点：**按"看一次输出"来定大小，不按"写多少行"来定。**

---

## 5. 明令禁止的 6 类伪任务

| ❌ | 例子 | 为什么不行 |
| --- | --- | --- |
| 实现一个系统 | "实现 Camera 系统" | 远超时间盒，且必然留半成品 |
| 学习性任务 | "了解一下 ANSI 转义序列 / DDA 原理" | 没有产出，无法验收 |
| 跨文件重构 / 改接口签名 | "把 FrameBuffer 改成 RAII" | 违反可中断，被打断就是死状态 |
| 需要多轮调试才能定论 | "查一下为什么偶尔会闪烁" | 5 分钟内得不到结论，只会带着焦虑被打断 |
| 无产出的检查 | "再读一遍 FrameBuffer 看看有没有问题" | 这是焦虑，不是任务 |
| **给用户 3~5 个选项让他挑** | "你可以考虑 A/B/C" | 上班空档最不需要的就是做选择。**给一个。** |

## 6. 类型轮换表（防止每次都是"改个值"）

| 类型 | 例子 | 档位 |
| --- | --- | --- |
| 改一个数 | `targetFps` 60→144、子弹速度、AI 距离阈值、FOV | 3~5 |
| 补一条断言 | `Vec2::Normalized` 的零向量、AABB 边界相接 | 5 |
| 看一次真实输出 | 打印 `dt` / `max dt` / 碰撞结果 | 5 |
| 删一行 | 去掉每帧 `ESC[2J`、删掉一个 hack | 5 |
| 加一行 Debug 显示 | F2 画碰撞盒、顶栏多显示一个数 | 10 |
| 换一张常量表 | 字符集 `█▓▒░`、颜色编号 | 10 |
| 写 5 行小函数 | `clamp` / `lerp` / `RoundToInt` + 注释 | 10 |

**连续两次触发不得给同一类型。**

## 7. 三个真实示例（照这个粒度做）

### 例 A（5 分钟档）

```text
[任务] 把限帧目标改成 144，看限帧是否真的生效 —— 预计 5 分钟
为什么是现在：S3 的验收标准之一；顺便验证已知风险 E-5（Windows Sleep 精度）

动手：
  1. engine/include/mini/core/Application.h 的 AppConfig::targetFps 60 → 144
  2. 增量构建：cmake --build build --config Debug

完成标志：顶栏 FPS 从 ~60 升到 140 上下（±5）；若仍是 32 或 60，说明撞上了 E-5
被打断怎么办：改回 60 即可，是单个字面量，无半成品状态
```

### 例 B（10 分钟档）

```text
[任务] 记录并显示本帧最大 dt —— 预计 10 分钟
为什么是现在：S3 验收要求"dt 长时间运行不出现尖峰"，现在无法观测

动手：
  1. engine/include/mini/core/Time.h → 加成员 float m_maxDt
  2. engine/src/core/Time.cpp → Update() 末尾 m_maxDt = std::max(m_maxDt, m_delta)
  3. 顶栏拼接处 → 多输出一个 maxDt

完成标志：跑 10 秒，maxDt 稳定在 0.017 附近；若出现 > 0.05 的尖峰说明有限帧抖动
被打断怎么办：三步都是加法，没改任何既有签名；中途丢下也能编译
```

### 例 C（"太难"的降级，不是换赛道）

用户说「太难」，不要重开一个话题，而是**同一件事砍到只剩一下**：

```text
[任务] 只做一件事：把 Time::LimitFPS 里那个 2ms 的自旋边界改成 1ms —— 预计 3 分钟
为什么是现在：E-5 的混合睡眠就差这个数字没试过
动手：engine/src/core/Time.cpp → 找 sleep 前预留的那 2 毫秒，改成 1
完成标志：FPS 仍是 ~60（不掉到 32）就算通过
被打断怎么办：改回 2 即可
```

## 8. 为什么"不做什么"比"做什么"更重要（上班场景三条）

1. 上班空档的敌人是**上下文重载**，不是时间不够 → 任务必须自带"打开哪个文件哪一行"。
2. 随时可能被叫走 → 任务**不许留下半成品状态**，宁可小到看起来"不值一提"。
3. 5 分钟里真正敲代码约 3 分钟，其余是构建和看输出 → 所以粒度按"**看一次输出**"定，不按行数定。

---

## 9. 和 `MiniEngine_PLAN.md` 的分工

| | 管什么 |
| --- | --- |
| `MiniEngine_PLAN.md` | 做什么、什么顺序、什么算做完、有哪些风险（阶段 S0~S14、验收标准、E 表） |
| `WORK_MODE.md`（本文件） | 把**当前**阶段切出一个 5~10 分钟的口子 |

冲突时**以 PLAN 为准**。本开关**不新增阶段、不改变顺序、不做设计决策**。

---

## 10. 这个开关**不适合**干的事

- ❌ **今天有 3 小时** → 那不该用上班模式，直接按 PLAN 的 H 节推进整个阶段。
- ❌ **需要设计决策的事**（"ECS 要不要上""接口怎么切"）→ 记成 TODO，留给整块时间。上班模式下给这种任务等于制造半成品。
- ❌ **替代 S0 骨架**。骨架是 60 分钟起的一次性投入，不在这个开关的射程内。
- ❌ **当进度追踪器用**。进度看 `git log` 和 PLAN，不看这里。
- ❌ **代写实现**。本开关**只发任务卡**（说清"改哪个文件哪一行、改成什么"），代码一律由我自己敲。
  这是 `AGENTS.md` 的核心约定：AI 默认只到方案层级。**若我明说"你写"才动手**，且只写我点到的那部分。
